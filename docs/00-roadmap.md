## Phase 2：コア試作（次に着手）

決め打ちの譜面1曲を、手応えのある操作感で遊べる状態にする。音楽ゲームの出来はここでほぼ決まる。

- 作るもの：`core/timing`、`core/chart`、`core/score`、`platform/input`、`game` のプレイ進行、曲の再生、ノーツ描画とオブジェクトの使い回し、ロングノーツ、同時押しの線
- 対象の要件：FR-01〜07、FR-10〜15、FR-31、NFR-01〜05、NFR-10〜11
- 完了の条件：
  - [ ] 自作曲1曲（仮の音源でも可）を 4〜7 レーンで最後まで遊べる
  - [ ] 手で叩いて、音と判定のずれを感じない（オフセット調整後）
  - [ ] 詳細設計書 10 章の core・game のテストがそろい、通っている
  - [ ] 判定幅の初期値を実際に試し、必要なら設計書を更新している
- 着手前に必要なもの：自作曲1曲（なければ仮の音源で進める）

## Phase 3：譜面データとエディタ

- 作るもの：譜面エディタ、曲情報・譜面ファイルの読み込み
- 対象の要件：FR-50〜52、FR-54、FR-60〜63
- 完了の条件：エディタで作った譜面を、そのまま遊べる
- 着手前に決めること：曲の数と、難易度の段階

## Phase 4：ゲームとしての形

- 作るもの：全画面（タイトル〜リザルト）、設定、判定タイミング調整、記録の保存
- 対象の要件：FR-16〜18、FR-20〜26、FR-30〜35、FR-40〜41
- 完了の条件：曲を選んで遊び、記録が残り、設定が次回に引き継がれる
- このフェーズで決めること：スコアの配点、クリアゲージの増減量

## Phase 5：演出と手触り

- 作るもの：ヒットエフェクト、判定・コンボの演出、効果音、曲ごとのテーマ、曲の試聴
- 対象の要件：FR-53
- 完了の条件：テストプレイで「叩いて気持ちいい」と言える
- 着手前に決めること：曲ごとのテーマで、どこまで見た目を変えるか

## Phase 6：品質確認

- 作るもの：対応ブラウザ（Chrome / Edge / Firefox / Safari）での確認と修正、性能の計測
- 対象の要件：NFR-10〜13、NFR-21〜22、NFR-31〜32、音源の形式（基本設計書 5.2）
- 完了の条件：対応ブラウザすべてで、音と判定のずれと性能の要件を満たす

## Phase 7：公開

- 作るもの：公開の自動化（main へのマージで公開）
- 完了の条件：公開した URL で遊べる
- 着手前に決めること：公開先（GitHub Pages を第一候補）
- 発展案（今回の範囲外）：オンラインランキング、譜面の共有、リプレイ、PWA 化
