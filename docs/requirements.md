# 要件定義書

| 項目     | 内容                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 対象     | game_music（ブラウザ音楽ゲーム）                                                              |
| 版       | 0.1（2026-11-25）                                                                             |
| 関連文書 | [基本設計書](basic-design.md) / [詳細設計書](detailed-design.md) / [ロードマップ](roadmap.md) |

## 1. 目的と概要

PC ブラウザで遊べる、縦に落ちてくるノーツ型の音楽ゲームを作る。自作曲を収録し、大手の商用タイトルと比べても遜色のない「判定の正確さ」と「叩いたときの気持ちよさ」を目指す。

成功の基準は次の3点とする。

1. 判定のずれを、プレイヤーが体感できない水準（後述の NFR-01〜03）に抑える
2. 4〜7 レーンのどのモードでも、同じ品質で遊べる
3. 追加の作業なしに、新しい曲と譜面を足せる（譜面エディタとデータ形式で担保）

## 2. 前提と制約

| ID   | 内容                                                         |
| ---- | ------------------------------------------------------------ |
| C-01 | 対象は PC のみ。操作はキーボード。スマホ・タブレットは対象外 |
| C-02 | 楽曲はすべて自作曲。第三者の楽曲・素材は使わない             |
| C-03 | 静的サイトとして配信する（サーバー側の処理を持たない）       |
| C-04 | 技術構成は TypeScript / Vite / PixiJS / Web Audio API とする |
| C-05 | 開発環境は Node.js 26 LTS 以上                               |

## 3. 対象環境

| 項目               | 要件                                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------------------- |
| ブラウザ           | Chrome / Edge / Firefox / Safari の最新版と、その1つ前の版                                               |
| 画面               | 1280×720 以上。ウィンドウサイズの変更に追従する                                                          |
| リフレッシュレート | 60Hz〜240Hz。リフレッシュレートが違ってもノーツの速さと判定は変わらない                                  |
| 入力               | 物理キーボード。キー配置は `KeyboardEvent.code`（物理キー位置）で扱い、JIS / US 配列の違いに影響されない |

## 4. 機能要件

### 4.1 ゲームプレイ

| ID    | 要件                                                                          |
| ----- | ----------------------------------------------------------------------------- |
| FR-01 | ノーツは画面上から判定ラインに向かって縦に落ちる                              |
| FR-02 | レーン数は 4〜7 で選べる。キー配置の初期値は下表のとおり                      |
| FR-03 | ノーツの種類は「通常ノーツ」と「ロングノーツ」の2種類                         |
| FR-04 | 同じ時刻にある複数のノーツ（同時押し）は、線でつないで強調表示する            |
| FR-05 | ロングノーツは、押し始めと離すタイミングの両方を判定する                      |
| FR-06 | ノーツの色は中央から左右対称に配色し、奇数レーンの中央（Space）は専用色にする |
| FR-07 | 曲の途中で一時停止・再開・リトライ・中断ができる                              |

| レーン数 | キー配置          |
| -------- | ----------------- |
| 4        | D F J K           |
| 5        | D F Space J K     |
| 6        | S D F J K L       |
| 7        | S D F Space J K L |

### 4.2 判定とスコア

| ID    | 要件                                                                                 |
| ----- | ------------------------------------------------------------------------------------ |
| FR-10 | 判定は Perfect / Great / Good / Miss の4段階                                         |
| FR-11 | 判定幅の初期値は Perfect ±33ms、Great ±66ms、Good ±100ms。これより遅れたら Miss      |
| FR-12 | Good の幅より早い入力は判定の対象にしない（空打ちとして扱う）                        |
| FR-13 | プレイ中に判定と、ずれの向き（早い / 遅い）を表示する                                |
| FR-14 | スコアは満点 1,000,000 点。判定の内訳で決まり、コンボ数には左右されない              |
| FR-15 | コンボを数え、Miss で 0 に戻る                                                       |
| FR-16 | クリアゲージを持ち、曲の終了時に基準値以上ならクリアとする                           |
| FR-17 | 曲の終わりに、スコア・判定の内訳・最大コンボ・クリア可否・早遅の件数を表示する       |
| FR-18 | 全ノーツ Great 以上でフルコンボ、全ノーツ Perfect でオールパーフェクトとして記録する |

### 4.3 画面

| ID    | 画面               | 主な内容                                                           |
| ----- | ------------------ | ------------------------------------------------------------------ |
| FR-20 | タイトル           | 開始操作。ここで音声を有効にする（ブラウザの自動再生制限への対応） |
| FR-21 | 曲選択             | 曲の一覧、試聴、ハイスコアの表示、レーン数の選択                   |
| FR-22 | 難易度選択         | 曲ごとの難易度の一覧とレベル                                       |
| FR-23 | プレイ             | ゲーム本体                                                         |
| FR-24 | リザルト           | FR-17 の内容、ハイスコアの更新表示、リトライ                       |
| FR-25 | 設定               | FR-30〜34 の項目                                                   |
| FR-26 | 判定タイミング調整 | オフセットを測って合わせる専用の画面                               |

### 4.4 設定

| ID    | 要件                                                            |
| ----- | --------------------------------------------------------------- |
| FR-30 | ノーツの落ちる速さを変えられる                                  |
| FR-31 | 判定のオフセット（音声・入力の遅延補正）を 1ms 単位で変えられる |
| FR-32 | 表示のオフセット（画面の遅延補正）を、判定とは別に変えられる    |
| FR-33 | 曲・効果音の音量を別々に変えられる                              |
| FR-34 | レーン数ごとにキー配置を変えられる                              |
| FR-35 | 設定はブラウザに保存し、次回の起動時に引き継ぐ                  |

### 4.5 記録

| ID    | 要件                                                                                                                 |
| ----- | -------------------------------------------------------------------------------------------------------------------- |
| FR-40 | 曲・難易度・レーン数ごとに、ハイスコア・最大コンボ・クリア状況を保存する                                             |
| FR-41 | 保存先はブラウザ（localStorage）とする。データ形式には版番号を付け、形式が変わっても古いデータを読み込めるようにする |

### 4.6 楽曲と譜面

| ID    | 要件                                                                           |
| ----- | ------------------------------------------------------------------------------ |
| FR-50 | 1曲は「音源」「譜面（難易度ごと）」「曲情報」「テーマ」で構成する              |
| FR-51 | 譜面は BPM の変化と拍子の変化を扱える                                          |
| FR-52 | 譜面は、曲ごと・レーン数ごとに用意する                                         |
| FR-53 | 曲ごとにテーマ（背景・色）を切り替える                                         |
| FR-54 | 曲ごとに音源のオフセット（音源の頭の無音やエンコーダーによる遅延）を補正できる |

### 4.7 譜面エディタ（開発用）

| ID    | 要件                                                          |
| ----- | ------------------------------------------------------------- |
| FR-60 | 曲を再生しながら、キーを叩いてノーツを記録できる              |
| FR-61 | 拍のグリッド（1/4〜1/32 拍、3連符）に合わせて配置・修正できる |
| FR-62 | 再生速度を落として確認できる                                  |
| FR-63 | 譜面を JSON で読み込み・書き出しできる                        |

## 5. 非機能要件

### 5.1 タイミング精度（最重要）

| ID     | 要件                                                                                                                |
| ------ | ------------------------------------------------------------------------------------------------------------------- |
| NFR-01 | 時刻の基準は音声の時計（`AudioContext`）だけとする。描画の時刻やシステム時計を判定に使わない                        |
| NFR-02 | 入力の時刻は、イベントが発生した時刻（`KeyboardEvent.timeStamp`）で判定する。フレームの処理タイミングに左右されない |
| NFR-03 | 判定ロジックそのものの誤差は 1ms 未満とする（単体テストで保証）                                                     |
| NFR-04 | 長時間（10分）のプレイでも、音と判定・表示がずれていかない                                                          |
| NFR-05 | フレーム落ちが起きても、ノーツの位置と判定は正しいままとする                                                        |

### 5.2 性能

| ID     | 要件                                                                                                |
| ------ | --------------------------------------------------------------------------------------------------- |
| NFR-10 | 一般的な PC で、プレイ中は画面のリフレッシュレートに張り付いて動く（60Hz で 1フレーム 16.7ms 以内） |
| NFR-11 | プレイ中にメモリの確保・解放による引っかかり（GC による停止）を起こさない。ノーツなどは使い回す     |
| NFR-12 | 初回の読み込みは、一般的な回線で 3 秒以内に操作可能になる                                           |
| NFR-13 | 曲の読み込みが終わってから再生を始める。再生中に読み込み待ちが起きない                              |

### 5.3 品質と保守性

| ID     | 要件                                                                                                            |
| ------ | --------------------------------------------------------------------------------------------------------------- |
| NFR-20 | TypeScript の strict モードで、型エラーなしとする                                                               |
| NFR-21 | 判定・時刻計算・スコア計算などのロジックは描画から切り離し、単体テストを書く。この部分の網羅率（行）は 90% 以上 |
| NFR-22 | 画面の主要な流れは E2E テスト（Playwright）で確認する                                                           |
| NFR-23 | 整形・lint・型チェック・テスト・ビルドを CI で毎回実行し、失敗したものはマージしない                            |
| NFR-24 | 仕様を変えたら、同じ変更の中で設計書を更新する                                                                  |

### 5.4 その他

| ID     | 要件                                               |
| ------ | -------------------------------------------------- |
| NFR-30 | 外部のサーバーに個人情報を送らない                 |
| NFR-31 | 色だけで情報を伝えない（判定は文字でも表示する）   |
| NFR-32 | 音声を再生できない環境では、その旨を画面に表示する |

## 6. 対象外（今回の範囲に含めないもの）

- スマホ・タブレット・ゲームパッドへの対応
- オンラインランキング、アカウント、データの同期
- ユーザーが持ち込んだ曲で遊ぶ機能
- 譜面の自動生成

いずれも、必要になった時点で改めて要件を追加する。
