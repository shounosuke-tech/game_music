# ブラウザ音楽ゲーム開発ロードマップ

## 概要

ブラウザで動く音楽ゲームを、8つのフェーズ（Phase 0〜7）に分けて開発します。最優先はPhase 2のコア試作で、叩いたときの気持ちよさとタイミング精度をここで固めます。

- 方針1：演出より先に「判定がずれない」ことを確定させる
- 方針2：各フェーズの終わりに、遊べる成果物を必ず1つ作る
- 方針3：未決定の事項は、そのフェーズに入る前に確認する（末尾の「確認事項」を参照）

```
P0 コンセプト → P1 技術の土台 → [P2 コア試作] → P3 譜面とエディタ
   企画メモ       音が鳴る最小構成   1曲遊べる試作品    譜面を自作できる
                                                          ↓
P4 ゲームの形 → P5 演出と手触り → P6 品質確認 → P7 公開と運用
   画面遷移とスコア  エフェクトと効果音  端末別のテスト   Webで公開
```

## Phase 0：コンセプトと要件定義

何を作るかを決めるフェーズです。成果物は1ページの企画メモです。

- ゲーム形式：縦に落ちてくるノーツ型、横に流れるレーン型、円形、画面タップ型など
- 操作方法：キーボード、タッチ、マウス、ゲームパッド
- 対象端末：PCのみか、スマホも含めるか（スマホは音の遅延とタッチ処理が難しくなる）
- 楽曲：自作曲、フリー素材、ユーザー持ち込み（権利の確認が必要）
- 規模とゴール：個人の試作、一般公開、ポートフォリオ

## Phase 1：技術の土台

画面に何かが表示され、音が鳴るだけの最小構成を作ります。技術は次の3案から選びます。

| 案  | 構成                                   | 長所                             | 短所                           |
| --- | -------------------------------------- | -------------------------------- | ------------------------------ |
| A   | TypeScript + Canvas 2D + Web Audio API | 軽い。仕組みを理解しやすい       | 演出を増やすと自前実装が増える |
| B   | PixiJS（WebGL） + Web Audio API        | 描画が速く、演出を多く入れやすい | ライブラリの学習が必要         |
| C   | Phaser                                 | シーン管理など機能が揃っている   | 音ゲーに不要な機能も多い       |

開発環境は Vite、TypeScript、ESLint / Prettier、Git を想定しています。

## Phase 2：コア部分の試作（最重要）

決め打ちの譜面1曲を、手応えのある操作感で遊べる状態にします。音楽ゲームの出来は、ここで作るタイミング精度でほぼ決まります。

- 時間の基準：`AudioContext.currentTime` を使う（`Date.now()` や `requestAnimationFrame` の時刻はずれが出る）
- ノーツの描画：曲の現在時刻から位置を毎回計算する（フレームごとに座標を足す方式は使わない）
- 入力の判定：`performance.now()` で取った入力時刻を音声の時刻に変換して判定する
- 判定幅の初期案：Perfect ±33ms、Great ±66ms、Good ±100ms、それ以外は Miss（試しながら調整）
- オフセット調整：端末ごとの音声・入力の遅延を補正する機能（ほぼ必須）

## Phase 3：譜面データとエディタ

譜面を自分で作って遊べる状態にします。

- 譜面フォーマット（JSON）：BPM、BPMの変化、ノーツの種類、ロングノーツ
- BPMと拍から秒への変換処理
- 簡易譜面エディタ：曲を再生しながらキーを叩いて記録し、グリッドに合わせる

## Phase 4：ゲームとしての形

一通り遊べるゲームに仕上げます。

- 画面の流れ：タイトル → 曲選択 → 難易度選択 → プレイ → リザルト
- スコア、コンボ、ゲージ、クリア判定
- 設定：ノーツの速さ、オフセット、音量、キー配置
- ハイスコアの保存（最初は localStorage）

## Phase 5：演出と手触り

叩いて気持ちいいゲームに磨き上げます。

- ヒットエフェクト、判定表示、コンボ演出、背景の動き
- 叩いたときの効果音（Web Audioで鳴らして遅延を減らす）
- 一時停止、リトライ、読み込み中の表示、曲の試聴
- フレームレートの安定（オブジェクトの使い回し、描画の最適化）

## Phase 6：品質確認

対象の端末とブラウザで、同じように遊べることを確認します。

- 対象ブラウザ：Chrome、Safari、Firefox、iOS、Android
- iOS Safariの対策：画面を触るまで音が鳴らない制限、音声の遅延
- 判定精度の確認と、テストプレイの感想をもとにした難易度調整

## Phase 7：公開と運用

他の人が遊べる場所に公開します。

- 公開先：GitHub Pages、Vercel、Netlify など
- PWA化してオフラインでも遊べるようにする（任意）
- 発展案：オンラインランキング（Supabase、Firebase など）、譜面の共有、リプレイ機能

## 確認事項

Phase 0の主要な項目はすべて決まりました。未決定の項目は、関係するフェーズに入る前に確認します。

| 項目         | 決定内容                                                                                                    |
| ------------ | ----------------------------------------------------------------------------------------------------------- |
| ゲーム形式   | 縦に落ちてくるノーツ型                                                                                      |
| 対象端末     | PCのみ（キーボード操作）                                                                                    |
| 楽曲         | 自作曲                                                                                                      |
| ゴール       | 大手でも採用する構成で、高いクオリティを目指す                                                              |
| 技術構成     | TypeScript + Vite + PixiJS（WebGL描画）+ Web Audio API。テストは Vitest と Playwright、CI は GitHub Actions |
| レーン数     | 4〜7レーンで可変。4：D F J K ／ 5：D F Space J K ／ 6：S D F J K L ／ 7：S D F Space J K L                  |
| ノーツの種類 | 通常ノーツ、ロングノーツ、同時押しの強調表示                                                                |
| ビジュアル   | 曲ごとに背景や色を切り替える                                                                                |
